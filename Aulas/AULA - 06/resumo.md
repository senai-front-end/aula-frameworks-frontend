# Projetos Front-End

## 1. Gestão de Projetos

Gerenciar um projeto Front-End significa organizar:

* Pessoas;
* Tarefas;
* Tecnologias;
* Prazos.

O objetivo é transformar uma ideia em uma **aplicação funcional**.

### Sem organização

Podem acontecer:

* Tarefas esquecidas;
* Requisitos confusos;
* Retrabalho;
* Conflitos no Git;
* Atrasos;
* Problemas de integração.

### Com organização

Temos:

* Responsabilidades claras;
* Prioridades definidas;
* Entregas menores;
* Acompanhamento do progresso;
* Menos retrabalho.

## 2. Requisitos

Um **requisito** descreve o que o sistema precisa fazer.

Exemplo:

```text
Requisito:
Sistema deve permitir gerenciamento de tarefas.
```

### User Story

Descreve uma funcionalidade do ponto de vista do usuário.

```text
Como usuário, quero criar uma tarefa.
```

### Tarefas

São as ações necessárias para desenvolver a funcionalidade:

* Criar formulário;
* Criar componente;
* Validar campos;
* Integrar API;
* Criar testes.

## 3. Backlog

O **Backlog** reúne tudo que precisa ser feito no projeto.

Pode conter:

* Funcionalidades;
* Melhorias;
* Correções;
* Outras atividades.

Os itens recebem **prioridades** para definir o que será feito primeiro.

## 4. Prioridade e Estimativa

### Prioridade

Define **o que deve ser feito primeiro**.

### Estimativa

Ajuda a entender a **complexidade e o esforço** de uma tarefa antes de realizá-la.

## 5. Definition of Done

**Definition of Done** são os critérios necessários para considerar uma tarefa concluída.

Exemplos:

* Código implementado;
* Testes realizados;
* Revisão concluída;
* Responsividade verificada;
* Integração realizada.

## 6. Scrum

**Scrum** é um framework ágil usado para desenvolver projetos de forma **incremental**, permitindo acompanhamento e entregas contínuas.

No Front-End, ajuda a:

* Organizar requisitos;
* Definir prioridades;
* Planejar Sprints;
* Acompanhar tarefas.
